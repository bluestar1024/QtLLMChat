# 消息线程与聊天记录

## overview

`MessageThread`（QThread 子类）模拟流式消息输出；`ChatRecordsWidget` 提供聊天记录管理（搜索/清空/回放），`ChatRecordStore`（chatrecordstore.h/cpp）封装 SQLite 聊天记录存取。三者共同支撑会话数据的"产生 — 展示 — 持久化 — 回放"闭环。

## architecture_design

### MessageThread（messagethread.cpp）

- 构造参数：`contentInput`（用户输入）、`context`（QList\<QVariantMap\> 上下文，预留 API 多轮对话）、`useStream`（是否流式）。
- `run()`：当前实现取全局常量 `testText_simple` 作为回复内容；流式时每 30 字符一包、间隔 500ms 发出 `newMessage`；非流式一次发完。
- `stop()`：`terminate()` + `wait()`（强制终止，非协作式取消）。
- **现状**：未发起真实 HTTP 请求；`contentInput` / `context` 目前未参与输出，为后续接入 OpenAI 兼容接口预留的接口面。

### ChatRecordsWidget（chatrecordswidget.cpp）

- 结构：头部（设置按钮 + 标题 + 搜索框 `LineEdit` + 清空按钮）+ 会话列表（`QListWidget`）。
- 模板连接器：`connectSettingButtonClick` / `connectLineEditTextChanged` / `connectSearchButtonClick` / `connectClearAllButtonClick` / `connectListItemClick` 各有 (无参) / (带 bool) 两种重载，供 MainWindow 灵活接入。
- 列表项数据：`listItemSetData` / `listItemToString` 以字符串承载会话 id（回放时转回 int 查询数据库）。

## data_model

聊天记录存于 SQLite 数据库 `../../chatrecords/chat_records.db`（`ChatRecordStore` 封装）：

- `chat_session(id, file_name, created_at)`：会话表，`file_name` 沿用 `chat_YYYY_MM_DD_HH_MM_SS.txt` 命名作标识。
- `chat_message(id, session_id, seq, content, think_time, is_user)`：消息表，`content` 为原始 Markdown（含 `<think>`），`think_time` 为思考时长（秒），`is_user` 区分用户/AI。

写入：`MainWindow::saveCurChatRecord()` 组装 `QList<ChatMessageRecord>` 后调 `ChatRecordStore::saveMessages()`——与库中现有消息逐条比较，仅从首个差异位置起删除重建（事务；内容相同不写库，流式追加为行内增长）。回放：`generateCurChatRecord()` 经 `loadMessages()` 按 `seq` 重建 `MessageWidget`（`thinkTimeIndex` / `expandIndex` 恢复展开状态）。

## gotchas_and_constraints

- `MessageThread::stop()` 使用 `terminate()`，可能中断在任意位置；接入真实网络请求后应改为协作式停止（标志位 + 网络超时）。
- 聊天记录数据库为可执行文件相对路径 `../../chatrecords/chat_records.db`，打包部署时需保证目录存在/可写；数据库打开/建表失败仅 qDebug 输出，`isOpen()` 为假时后续读写静默跳过。
- `saveCurChatRecord` 在 `isBuildingChatRecord` / `isChatRecordBuildAbandoned` 为真时跳过保存（避免把构建中的半成品消息列表写库截断会话）。
- `clearAllChatRecords` 清空列表并删除数据库全部会话/消息，需确认与主窗口的联动逻辑（避免正在回放的会话 id 失效）。

## coding_conventions

- 线程类通过信号（`newMessage`）与主线程通信，符合 Qt 跨线程事件模型。
- 聊天记录读写统一经 `ChatRecordStore`（QSqlQuery 预编译语句 + 绑定参数），中文/特殊字符无需转义；文本搜索用 `instr` 字面匹配，避免 LIKE 通配符转义问题。
